# 服务器上的路径与资源

## 默认目录

所有默认输出都相对于应用启动目录，不依赖开发机盘符。数据库中保存的会话文件路径仍相对于聊天存储根目录，不需要因本次调整修改表结构或历史数据。

```text
应用启动目录/
└─ tmp/
   ├─ file/用户ID/任务ID/      文件读写工具
   ├─ download/用户ID/任务ID/  运行时下载的资源
   ├─ pdf/用户ID/任务ID/       生成的 PDF
   └─ chat-memory/
      ├─ love/               恋爱助手记录与记忆
      │  └─ context-backups/ 摘要压缩备份
      └─ manus/              智能体记录与记忆
         └─ context-backups/
```

Java 在运行时会把聊天目录规范化为实际路径，用于校验文件是否仍位于允许目录内。这不等于在代码或数据库中写死服务器路径。

## 配置

```yaml
app:
  storage:
    base-dir: ./tmp
    file-retention: PT24H
    cleanup-interval: PT5M

chat-memory:
  base-dir: ${app.storage.base-dir}/chat-memory

pdf:
  fonts:
    regular: classpath:fonts/NotoSansSC-Regular.otf
    bold: classpath:fonts/NotoSansSC-Bold.otf
```

`APP_STORAGE_BASE_DIR` 覆盖工具和默认聊天存储根目录，`CHAT_MEMORY_BASE_DIR` 可单独指定聊天目录。`PDF_FONT_REGULAR`、`PDF_FONT_BOLD` 用于可选的自定义字体；默认字体已包含在应用中，不需要另行安装。

`APP_FILE_RETENTION` 覆盖工具文件保留时长，默认 `PT24H`（24 小时）；`APP_FILE_CLEANUP_INTERVAL` 覆盖扫描周期，默认 `PT5M`（5 分钟），两者必须为正时长。应用启动后执行首次清理，然后持续按间隔扫描。到期后立即拒绝下载，物理删除最多延后一个扫描周期。清理释放服务器磁盘空间。

从固定的应用目录启动，例如：

```sh
java -jar ./ai-agent-0.0.1-SNAPSHOT.jar --app.storage.base-dir=./data
```

相对路径以启动进程的工作目录为基准。通过服务管理器或容器启动时，也应固定工作目录，并让运行账号对数据目录有写入权限。迁移已有项目时，保留默认 `./tmp`，或先整体迁移原有数据目录，再更改存储配置。

配置也接受服务器挂载的数据目录，部署路径由启动配置决定，而不是写进 Java 源码。

## 地图与图片 MCP

地图使用高德官方 Streamable HTTP 服务 `https://mcp.amap.com/mcp`，图片继续使用原有 SSE 服务，两者会合并为模型可用的工具列表。部署时设置 `AMAP_MAPS_API_KEY`；本地已把原 `mcp-servers.json` 中的 Key 复用到被 Git 忽略的 `application-local.yml`，环境变量优先。

`mcp-servers.json` 只是 stdio 方式的备用配置。当前应用不加载它，不需要 `npx.cmd`、Node 或本地图片 MCP JAR。只有文件中存在配置而没有在 Spring 配置中启用对应连接，不会自动装配地图工具。高德连接在应用启动时初始化，启动前应配置有效 Key，并确保服务器可访问高德服务。

修改 MCP 配置或提示词后需重启后端。约会策划应先出现 `maps_text_search`、地点详情和必要的周边、路线调用，再生成 PDF；图片为可选项，不能把普通图库照片当成具体地点实景。高德官方接入方式见[快速接入文档](https://lbs.amap.com/api/mcp-server/gettingstarted)。

## 静态资源与运行时文件

- 固定字体放在 `src/main/resources/fonts`，PDF 工具从输入流读取，支持打进 JAR 后的资源。
- 知识库 Markdown 已在 `src/main/resources/document`，继续使用 classpath 资源加载。
- 下载结果、聊天记录和 PDF 是运行时产生的文件，保存在外部可写目录；不写入 JAR 内的 resources。
- 工具默认返回相对输出路径，PDF 图片参数同时接受相对路径和当前服务器上的绝对路径。
- 应用内工具同时返回真实 HTTP 下载链接；PDF 图片只允许引用当前用户的有效工具文件。原有工具无参构造方式仍可在本地独立使用，但不会生成带用户权限的网页下载链接。
- 终端工具在 Windows 使用 `cmd.exe`，在 Linux/Unix 使用 `sh`，不依赖固定的 Windows 可执行文件路径。

本地回归覆盖配置解析、文件读写、本机 HTTP 下载、中文 PDF 字体嵌入、相对图片引用、JAR 字体及 Markdown 资源加载，并复测账号、会话、取消和摘要压缩。AI/MCP 使用模拟服务；未连接真实 Linux 服务器执行部署。

本次下载与清理改造的后端回归共 116 项，115 项通过，1 项符号链接测试因当前 Windows 缺少创建符号链接权限跳过；前端 45 项通过。真实定时任务在测试短周期内自动清除了过期文件，下载测试使用实际文件与中文 PDF。浏览器另以临时附件响应验证点击产生下载、过期提示、普通外站链接和代码复制；未请求真实 AI 服务。前后端均完成构建打包。

## 浏览器下载与有效期

图片下载、PDF 生成和文本写入工具都会返回 Markdown 下载链接，例如 `/api/files/pdf/任务ID?name=报告.pdf`（实际文件名经过 URI 编码）。用户与任务信息来自后台运行上下文，工具参数中不能指定用户身份。下载接口要求登录，按当前用户目录查找文件，并复用账号切换检查，不能下载其他用户的文件。

前端点击这些链接时通过已有 API 客户端获取附件，自动使用 `VITE_API_BASE_URL`、Session 和账号标识，支持开发代理和前后端分离部署。普通外站链接仍照常打开。后端以附件流返回，不会把整个文件读取进服务器堆内存；响应不缓存，文件名支持中文。过期后显示“文件不存在或已过期，请重新生成后下载”。

24 小时从最后一次完整写入开始计算，重复下载不续期；同一任务重写同名文件会更新内容和时间。先写临时文件，成功后替换正式文件，避免下载到半成品。下载失败、生成失败留下的临时文件会及时删除，进程异常留下的旧临时文件也会被定时清理。

清理范围仅包含 `file`、`download`、`pdf` 三个工具目录，包括改造前留在这些目录中的旧文件。聊天记录、模型记忆、摘要备份、知识库和字体不受清理影响；单独配置到工具目录里的聊天根目录也会被跳过。清理不跟随符号链接，单个文件删除失败会记录日志并在下次重试。请勿将需要永久保存的资料放入这三个临时工具目录。

历史消息中的 `sandbox:` 链接没有可靠的用户归属信息，不自动开放下载；重新执行下载或生成任务后会得到新链接。终端工具自行写到其他任意位置的文件不自动公开为附件，应通过上述工具产生供用户下载的文件。本方案使用单实例本地存储；多实例部署需要共享同一持久化目录。
