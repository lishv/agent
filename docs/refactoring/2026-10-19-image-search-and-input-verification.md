# 图片搜索与输入上限修复

## 定位结果

- 用户日志中的三次小猫检索均被 MCP 客户端的 20 秒请求期限中断。重放时远程服务已恢复，三个关键词都能命中缓存，因此无法从当前在线状态断定当时每次请求的上游耗时。
- 在本地 HTTP 服务下复现了图片 MCP 的全局方法锁问题：一个慢上游查询会阻塞另一个用户的搜索。原方法整个网络请求都处于 `synchronized` 内。
- Pixabay `largeImageURL` 最大边通常为 1280px，原工具没有提供可用于区分预览图和 4K 原图的可靠下载尺寸。
- 前端聊天输入上限原为 8000，普通消息后端为 20000，补充回答后端原为 10000，错误提示又写成 8000，存在三种口径。

## 修改

- 图片 MCP 改用并发缓存，网络等待不再占用全局方法锁；上游连接超时为 3 秒、读取超时为 10 秒。
- 主后端保留原 MCP 图片检索，增加 Bing 图片备用检索。相同任务发生 MCP 错误后暂缓重复调用，其他地图工具保持原回调。
- `searchImage` 支持指定数量和目标尺寸，并保留真实图片地址、来源、作者与实际像素。读取图片头时使用限长流，不解码整张图片。
- **按用户最后确认：预览图和缩略图保留，不因小于 4K 而排除。** 用 `isPreview`、`meetsRequestedResolution` 标明是否达到目标尺寸，返回实际数量，不能把低分辨率图片声称为 4K 原图。
- 前端结果摘要展示实际图片来源、尺寸及预览标记，避免备用来源被写成 Pixabay。
- 两个助手共用增强后的图片回调；超级智能体提示词要求调用图片工具、核对数量，并给出具体图片链接。
- 聊天与补充回答统一为 20000 字符，前后端分别使用共享常量，字数统计阈值和错误提示同步调整。

## 验证

- 图片 MCP：13 项测试通过，包含慢请求与快速请求同时执行的并发回归。修复前该并发用例会超时，修复后快速请求独立完成。
- 主后端定向回归：覆盖图片数量、备用检索、保留缩略图、真实尺寸、错误信息、工具装配、文件下载、恋爱大师和智能体交互。
- 前端：45 项测试通过，生产构建成功；浏览器完成 23 组对话检查，包含 20000 字符完整提交、输入框禁止继续追加、长消息折叠和移动端。
- 后端边界：聊天消息和补充回答接受 20000 字符，超过 20000 字符返回参数错误；真实补充回答通过原交互通道完整交给工具。
- 真实工具验证：Pixabay 小猫 3 张、Bing 壁纸 5 张、模拟 MCP 不可用后的备用小猫 3 张，共 11 个图片文件均由原下载工具成功下载。5 张壁纸中保留了 4 张预览图。
- 真实模型运行原始请求「帮我搜索5张4K壁纸」「帮我找到三张小猫照片」均正常结束，各调用一次图片工具。最终答复分别给出 5 张壁纸链接（明确标注预览与实际尺寸）及 3 张小猫照片，未以网站目录代替图片。

工具与模型验证使用隔离的 `.tmp` 存储和测试用户上下文，不修改用户历史；实际模型使用现有 OpenAI 兼容配置。测试时图片链接可访问，不代表外部站点永远可用。备用检索依赖 Bing 搜索页结构，解析失败会返回明确失败或不足数量。

## 部署与产物

- 主后端：`target/ai-agent-0.0.1-SNAPSHOT.jar`，需要重启主后端加载新工具与输入上限。
- 图片 MCP：`image-search-mcp-server/target/image-search-mcp-server-0.0.1-SNAPSHOT.jar`，需要替换远程服务 JAR 并重启，才能启用并发与超时修复；本次没有远程部署。
- 前端：`ai-agent-frontend/dist/`。
- 证据：`.tmp/image-search-live.log`、`.tmp/image-agent-live/`、`.tmp/image-input-final-build.log`、`.tmp/image-server-final.log`、`ai-agent-frontend/.tmp/image-input-browser.log`。
