# 恋爱大师工具上下文修复与功能检查

## 已修复的问题

文件工具为实现用户隔离与网页下载，需要 Spring AI ToolContext。此前只有 Manus 运行入口传入身份，恋爱助手的流式入口遗漏了上下文，因此模型选择 downloadResource 后，在执行工具前抛出 `ToolContext is required by the method as an argument`。

现在 ChatApplicationServiceImpl 为每轮恋爱聊天生成独立任务 UUID，并将真实登录用户 ID 与任务标识交给 LoveApp。LoveApp 通过 `.toolContext(...)` 传入框架，同步工具入口也提供相同的上下文重载。身份不作为工具参数交给模型，不依赖 HTTP 线程局部变量，也不依靠从 chatId 推断用户。原有两参方法仍保留；独立调用受保护文件工具时，应使用带上下文的重载，由可信业务入口提供身份。

没有修改聊天模型、嵌入模型、内存参数、知识库开关或数据库结构。

## 验证边界

代码流程使用真实 ChatClient、Advisor、工具执行器、DashScope 模型适配器、文件记忆、测试数据库及本机 HTTP 服务。外部大模型、向量检索和 MCP 提供方的网络响应在自动回归中被替换为可控数据，没有发送真实邮件或修改真实数据库；测试不能保证外部服务在任意时刻都可用，也不评判大模型回答的内容质量。

此前独立实测图片 MCP 的初始化、工具列表与一次图片搜索成功；此前 Ollama 向量模型的资源不足问题不在本次修复范围内。
