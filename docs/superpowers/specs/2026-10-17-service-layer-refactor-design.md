# Controller、Service、Mapper 可读性重构

## 已确认的目标

保留现有三层结构与功能，简化代码、复用现有业务方法和 MyBatis-Plus，并为三个包中所有声明的方法（包含构造方法和内部类方法）补充准确的中文注释。用户已确认此方案，并要求在 ServiceImpl 中直接使用 MyBatis-Plus 能力，保持 Mapper 精简。

## 方案选择

采用按职责提取方法的渐进重构。仅补注释无法解决重复逻辑；引入通用 Controller、通用业务基类或函数式锁封装会增加阅读负担。本次保留现有接口方法及调用方式，让入口方法直接展示业务顺序。

## 具体调整

1. Controller：保留路由、请求体、返回结构及 SSE 事件，统一排版，明确方法的用途和返回含义。
2. AccountServiceImpl：继承 MyBatis-Plus ServiceImpl，使用 getById、lambdaQuery、lambdaUpdate 和 save；复用已有登录、密码更新和验证码方法；保持 BCrypt、认证版本与 Session/CSRF 轮换行为。
3. ConversationServiceImpl：继承 ServiceImpl，使用链式查询和更新；提取会话创建、归属检查与列表视图转换，消除已有会话的重复查询；保留会话锁、原子文件替换、逻辑删除与删除后禁止迟到写入的规则。
4. ManusRunServiceImpl：按参数校验、登记任务、绑定消息记录、准备上下文、启动执行、清理资源组织流程；复用正常结束和启动失败的资源清理，保留两者的消息收尾差异及锁顺序。
5. ContextMemoryServiceImpl：提取重复 Token 预算计算、压缩边界扫描与摘要结果组装；保持用户目标保留、工具调用配对、备份、失败回退、删除标记和锁范围。
6. Mapper：UserMapper 复用 BaseMapper；ChatSessionMapper 只保留包含逻辑删除记录的特殊查询。普通 MyBatis-Plus 查询会自动排除逻辑删除记录，不能替代这一特殊需求。
7. 注释：修正 memoryKey 返回值、own 返回值、shutdown 行为等不准确描述；明确可空返回、布尔返回、取消回调、锁内外执行和文件写入约束；不逐行复述赋值代码。
