# 工具文件下载与过期清理

用户已确认采用 HTTP 下载接口，并要求图片、PDF 等工具文件支持下载和 24 小时自动清理。本次沿用该方案直接实施。

## 方案与边界

采用本地文件系统与已有 Session 鉴权，新增文件服务统一管理输出路径、下载链接及过期判断。不引入数据库表、对象存储或沙箱。公开映射整个 tmp 目录会暴露聊天数据；对象存储适合多实例部署，但超出本次单机功能范围。

资源下载、PDF 生成及文本写入工具的新输出按 `工具目录/用户ID/任务ID/文件名` 保存。用户、任务身份由运行服务通过 Spring AI ToolContext 注入，不由模型提供。文件先写临时文件，完成后替换正式文件，避免下载到未完成结果。独立使用原有工具构造方法仍保留本地读写能力。

下载接口为 `GET /files/{category}/{runId}?name=...`，category 仅允许 download、pdf、file。服务按当前登录用户定位文件，检查路径与符号链接，阻止越权和目录穿越；使用附件响应流返回文件，支持中文名。返回给模型的 Markdown 链接包含实际 context-path，禁止拼接 sandbox 或 file 链接。前端经已有 API 客户端下载，以携带登录态、账号归属及自定义后端地址，并显示过期或失败提示。

## 保留与清理

默认保留 24 小时，从最后一次完整写入开始计时。下载不延长有效期。到期立即拒绝下载，定时任务启动后及每 5 分钟扫描一次三个工具目录，删除到期的正式和遗留临时文件，并移除空子目录。单个文件删除失败不会中断其他文件清理。定时任务不跟随符号链接；聊天记忆、知识库与字体不属于清理目标。老目录中已有的工具文件也按时间清理，但不自动为无法确认归属的历史文件开放下载。

配置使用 `app.storage.file-retention=24h` 和 `app.storage.cleanup-interval=5m`，允许部署时覆盖，必须为正时长。相对存储目录和现有环境变量保持适用。过期物理删除至多延后一个扫描周期。

## 实施与验证

1. 增加文件服务、下载 Controller、存储配置和清理任务，复用 Spring MVC、URI 编码及文件响应能力。
2. 三个工具复用服务管理写入与链接；运行服务注入不可由模型修改的用户和任务上下文；提示词要求使用工具返回的下载地址。
3. 前端拦截本项目下载链接，通过配置好的 API 地址获取文件，保留普通外部链接与代码复制功能。
4. 验证图片及真实中文 PDF 下载、文本读写、同名文件隔离、匿名与跨用户访问、特殊文件名、路径穿越、符号链接、24 小时边界、清理范围和重启读取。复测现有账号、会话、后台运行、取消、压缩与前端测试，完成打包。
