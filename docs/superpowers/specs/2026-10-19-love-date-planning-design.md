# 恋爱大师的地点检索与约会 PDF

## 已确认的问题

- `mcp-servers.json` 中已有高德配置，但加载该文件的 stdio 配置被注释；运行中仅连接图片 MCP。
- 默认 RAG 提示词要求只依据知识库回答，与需要实时地点信息的约会策划不匹配。
- 本次生成文件偏向通用沟通建议，图片为通用情侣照片，未形成合肥具体行程。

## 已获用户确认的方案

1. 通过高德官方 Streamable HTTP MCP 接入地图能力，复用现有 Key；保留现有图片 SSE 连接，不额外启动本地图片服务。服务器通过环境变量配置 Key，不依赖 `npx.cmd` 或本地 JAR 路径。
2. 为约会任务明确检索顺序：城市内地点搜索、地点详情、必要的周边及路线查询，再组织行程和 PDF。只有城市时不虚构用户位置；缺少喜好时明确假设，不重复询问已给出的城市和预算。
3. 保留现有知识库检索和记忆行为，仅调整增强提示词：情感资料是参考，地点事实以工具结果为依据，不能用资料替代用户本轮任务。
4. 地点照片必须有匹配地点的来源依据；普通图库图片不能冒充实景。找不到相关图片时生成纯文字 PDF，用户明确需要时才使用标注清楚的气氛示意图。
5. PDF 包含具体地点、地址、顺序、交通、预算分项和信息来源。无来源的消费金额标为估算，工具失败要如实说明，继续使用文件工具返回的下载链接。

## 实施与验收

- 将恋爱助手提示词独立保存，保持业务入口简洁。
- 通过真实 MCP HTTP 传输和本地测试服务验证实际配置会加载地图工具、传递 Key 并执行搜索。
- 通过真实 ChatClient / Advisor 验证用户请求和工具检索规则在有、无知识库命中时均保留，知识库资料不会写成用户历史。
- 回归工具执行、下载和记忆相关测试；实测官方地图接口，并在可用时验证真实模型对本次输入的工具选择及 PDF 内容。
- 测试替身只能证明接线与提示词传递，不能当作真实模型选择正确的证据；分别记录验证范围。
- 本次不调整模型、嵌入或运行内存参数。
