# 聊天消息中的图片预览

用户已确认：前端增加图片缩略图，保留下载和来源链接，复用现有鉴权下载接口，直接实施。后续明确范围：两个助手仅在最终回复中展示图片，过程消息不展示。

## 已验证的原因

`messagePresentation.js` 将图片搜索结果转换成普通 Markdown 链接，因此渲染结果没有图片元素。消息组件支持 Markdown，但没有从普通图片下载链接生成预览的功能。后端文件接口返回附件及二进制内容；浏览器实验已确认，通过现有 API 获取 Blob 后可正常显示图片，无需新增公开资源路径或修改后端接口。

## 设计

- 恋爱大师和超级智能体共用消息图片组件。仅在最终回复下方展示自适应缩略图，保留正文中的下载、来源链接。工具回执和执行步骤无论折叠还是展开，均不展示或自动加载图片。旧版恋爱记录缺少最终标记时，排除工具回执、显式进度消息和步骤后兼容普通回复。
- 图片搜索结果增加标准 Markdown 图片标记，使无扩展名的图片地址也能识别。图片下载链接、普通图片链接和显式 Markdown 图片统一从 Markdown 语法树提取；代码块、行内代码、来源网页及 PDF 等文件不自动当作图片。
- 同一条消息中的相同图片只预览一次。Markdown 图片由统一组件显示，避免原生图片和缩略图重复。
- 本站图片复用现有 API 客户端，携带账号身份、登录态及自定义 API 根地址，读取 Blob 并生成临时对象 URL。远程图片通过图片元素加载，失败时保留原链接。
- 图片进入视口附近才加载；支持加载中、加载失败/已过期及重试。组件销毁或账号变化时取消请求，释放对象 URL，防止旧请求重新显示上一个账号的图片。
- 下载调用继续复用已有方法；新增可选取消信号供预览使用。下载及预览不会延长后端文件的 24 小时有效期。

## 实施与验证

1. 补充图片搜索缺少图片标记的失败用例，验证当前原因。
2. 增加图片识别纯函数及预览组件，接入共用消息渲染，保留原有代码复制、下载、工具展示行为。
3. 验证普通/无扩展名/中文名图片、去重、Markdown 图片、流式更新、历史消息和代码中的图片示例。
4. 浏览器验证受保护的附件响应、预览与下载、过期错误和重试、两类助手、手机端、页面销毁及账号切换；验证只有最终回复展示图片，过程消息展开后也不展示或请求图片；检查没有多余请求或对象 URL 泄漏。
5. 运行前端测试和打包，使用本地模拟接口验证，不调用真实模型或修改后端运行配置。
