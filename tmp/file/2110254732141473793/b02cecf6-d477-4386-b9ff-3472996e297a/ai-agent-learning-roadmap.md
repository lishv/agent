# AI 智能体学习路线：从零基础到独立完成项目

> 适合对象：没有 AI 智能体经验，具备基本电脑操作能力，愿意学习一点 Python 的初学者。
>
> 建议周期：12 周，每周 6～10 小时。
>
> 学习目标：完成一个能够理解用户请求、调用工具、检索知识库、执行多步骤任务，并具备基本测试与安全控制的 AI 智能体应用。

## 一、最终要做出的项目

建议把最终项目定为一个“个人知识库学习助手”，功能包括：

1. 用户可以上传 Markdown、PDF 或 TXT 文档。
2. 用户可以针对文档提问。
3. 智能体能够检索相关内容并回答问题。
4. 回答中显示参考来源。
5. 智能体能够调用计算器、日期查询或网页搜索等工具。
6. 对不确定的问题明确说明，而不是编造答案。
7. 记录每次请求、工具调用、错误和耗时。
8. 提供一个简单的 Web 页面或 API。

这个项目规模适中，能够覆盖 AI 智能体最核心的知识，同时不会一开始就陷入复杂的多智能体系统。

# 第 1 阶段：Python 与开发环境

## 目标

能够创建一个 Python 项目，安装依赖，读取环境变量，处理文件，并运行一个简单程序。

## 第 1 步：安装基础工具

学习内容：

- Python 3.11 或更高版本。
- VS Code 或其他代码编辑器。
- Git 的基本使用。
- 命令行的基本操作。
- 虚拟环境和依赖安装。

需要掌握的命令：

```bash
python --version
python -m venv .venv
# Linux 或 macOS
source .venv/bin/activate
# Windows PowerShell
.venv\Scripts\Activate.ps1
pip install requests python-dotenv
```

动手任务：

1. 新建一个项目目录。
2. 创建虚拟环境。
3. 创建 `requirements.txt`。
4. 创建 `main.py`，打印一行文字。
5. 创建 `.gitignore`，忽略 `.venv` 和 `.env`。

阶段产出：

```text
ai-agent-project/
├── .gitignore
├── .env.example
├── requirements.txt
└── main.py
```

进入下一步的标准：

- 你能够从命令行创建并运行 Python 文件。
- 你知道虚拟环境的作用。
- 你不会把 API Key 写死在代码里或提交到 Git。

## 第 2 步：补齐必需的 Python 基础

学习内容：

- 变量、字符串、数字、布尔值。
- 列表、字典、集合和元组。
- `if`、`for`、`while`。
- 函数和参数。
- 文件读写。
- JSON 读写。
- 异常处理。
- 模块和 `pip`。

暂时不需要深入学习：

- 复杂算法。
- 高级面向对象设计。
- 深度学习框架。
- 复杂的异步编程。

动手任务：

写一个程序，读取 `notes.txt`，统计：

- 总字符数。
- 总行数。
- 每个关键词出现的次数。
- 将结果保存到 `result.json`。

进入下一步的标准：

- 能读懂一个 50～100 行的 Python 示例。
- 能自己编写函数并处理异常。
- 能使用字典处理结构化数据。

# 第 2 阶段：调用大模型 API

## 目标

理解模型调用的基本流程，并完成一个可以多轮对话的命令行程序。

## 第 3 步：理解大语言模型的基本概念

学习内容：

- 大语言模型是什么。
- Token 和上下文窗口。
- 模型输入与输出。
- 系统消息、用户消息、助手消息。
- Temperature、最大输出长度和模型选择。
- 模型为什么会产生幻觉。
- API Key、请求、响应和错误码。

必须形成的认识：

- 模型不是数据库。
- 模型输出不是天然正确的。
- 模型只能看到当前请求中提供给它的上下文。
- 需要用程序校验模型输出。

阅读资料时，优先选择所使用模型厂商的官方 API 文档。

## 第 4 步：完成第一次模型调用

动手任务：

编写程序，实现：

1. 从 `.env` 读取 API Key。
2. 读取用户输入。
3. 调用模型。
4. 打印模型回答。
5. 捕获网络错误和 API 错误。
6. 记录本次请求的耗时。

推荐程序结构：

```text
project/
├── main.py
├── config.py
├── model_client.py
├── .env
└── requirements.txt
```

阶段产出：

一个命令行问答程序，例如：

```text
用户：解释什么是 RAG
助手：RAG 是一种让模型先检索外部资料，再根据资料生成回答的方法。
```

进入下一步的标准：

- 能够独立完成一次 API 调用。
- 能够解释请求参数和响应内容。
- 遇到 API 失败时程序不会直接崩溃。

## 第 5 步：加入多轮对话

学习内容：

- 对话历史的保存方式。
- 上下文长度限制。
- 历史消息过长时的截断或摘要。
- 会话 ID 的概念。

动手任务：

给命令行助手增加：

- 连续多轮对话。
- `clear` 命令清空历史。
- `save` 命令保存对话。
- `exit` 命令退出程序。

进入下一步的标准：

- 程序能记住当前会话中的信息。
- 你能解释“会话记忆”和“模型本身记忆”的区别。

# 第 3 阶段：提示词与结构化输出

## 目标

让模型稳定完成任务，并输出程序能够读取和校验的数据。

## 第 6 步：学习提示词的组成

每个任务至少明确以下内容：

1. 角色：模型应该以什么身份工作。
2. 目标：需要完成什么任务。
3. 输入：模型可以使用哪些资料。
4. 规则：必须遵守哪些约束。
5. 输出格式：应该返回什么结构。
6. 异常情况：信息不足时应该怎么做。

推荐模板：

```text
你是一个专业的会议纪要整理助手。

任务：从输入文本中提取会议结论和待办事项。

规则：
- 只能根据输入内容回答。
- 找不到信息时使用 null。
- 不要补充输入中没有出现的事实。
- 输出必须符合指定 JSON 结构。

输入：
{meeting_text}
```

## 第 7 步：完成文本分类器

动手任务：

制作一个客服邮件分类器，把邮件分为：

- 售前咨询。
- 订单问题。
- 退款问题。
- 技术故障。
- 投诉。
- 其他。

要求输出：

```json
{
  "category": "订单问题",
  "urgency": "medium",
  "reason": "用户询问订单配送状态",
  "confidence": 0.86
}
```

重要实践：

- 不要只打印模型返回的字符串。
- 用 JSON 解析器或数据模型校验字段。
- 缺少字段时进行错误处理。
- 对置信度进行范围检查。

## 第 8 步：完成信息提取器

动手任务：

从简历、发票或会议记录中提取：

- 人名。
- 日期。
- 金额。
- 组织名称。
- 待办事项。
- 联系方式。

准备至少 20 条测试文本，其中包括：

- 正常输入。
- 缺少字段的输入。
- 格式混乱的输入。
- 含有歧义的输入。
- 与任务无关的输入。

进入下一阶段的标准：

- 模型输出能够被程序解析。
- 你有一批固定测试数据。
- 你能记录错误类型，而不是只凭主观感觉判断效果。

# 第 4 阶段：工具调用

## 目标

让模型能够根据用户请求选择工具，但由程序负责真正执行、校验和限制工具。

## 第 9 步：先学会普通函数工具化

先不要接入复杂框架。用普通 Python 函数实现：

- 计算器。
- 日期计算器。
- 本地文件搜索。
- 天气查询或公开信息查询 API。

每个工具都要有：

- 工具名称。
- 功能说明。
- 参数定义。
- 参数校验。
- 返回值格式。
- 超时和错误处理。

示例：

```python
def calculate(expression: str) -> dict:
    """计算受限表达式，并返回结构化结果。"""
    ...
```

注意：不要直接对用户输入使用不受限制的 `eval`。

## 第 10 步：理解模型发起工具调用的流程

典型流程：

```text
用户请求
  -> 模型判断是否需要工具
  -> 模型返回工具名称和参数
  -> 程序校验工具名称和参数
  -> 程序执行工具
  -> 工具结果返回给模型
  -> 模型生成最终回答
```

动手任务：

制作一个“生活事务助手”，支持：

- 计算两个日期之间的天数。
- 计算账单总额。
- 搜索本地笔记。
- 查询当前天气。

要求：

- 工具参数必须经过校验。
- 工具失败时返回明确错误。
- 工具调用过程写入日志。
- 模型不能直接执行任意代码。

进入下一步的标准：

- 你能区分模型决策和程序执行。
- 你能为工具增加参数校验和权限限制。
- 你知道哪些操作必须经过人工确认。

# 第 5 阶段：工作流与任务分解

## 目标

让智能体稳定地完成多步骤任务，而不是完全依赖模型自由发挥。

## 第 11 步：学会拆解任务

把复杂任务拆成：

1. 接收请求。
2. 判断请求类型。
3. 提取必要信息。
4. 查询资料或调用工具。
5. 检查结果。
6. 生成中间结果。
7. 请求人工确认，或继续执行。
8. 生成最终结果。

示例：客户邮件处理流程：

```text
读取邮件
  -> 提取订单号和问题
  -> 判断优先级
  -> 检索处理政策
  -> 生成回复草稿
  -> 高风险问题转人工
```

## 第 12 步：实现一个确定性工作流

动手任务：

实现“会议纪要处理器”：

1. 读取会议文本。
2. 提取会议主题。
3. 提取结论。
4. 提取待办事项。
5. 为待办事项整理负责人和截止时间。
6. 输出 Markdown 文件。

要求：

- 每一步有清晰输入和输出。
- 某一步失败时可以定位原因。
- 不要把所有任务塞进一次模型调用。
- 允许用户修改中间结果。

## 第 13 步：增加状态和人工确认

学习内容：

- 状态对象。
- 任务 ID。
- 任务步骤。
- 暂停、恢复和失败。
- 人工确认节点。

动手任务：

给会议处理器增加一个确认步骤：

```text
提取待办事项
  -> 显示待办事项
  -> 用户确认或修改
  -> 生成最终任务清单
```

进入下一阶段的标准：

- 你能设计至少 3 步的任务流程。
- 每一步的结果都可以被检查。
- 涉及发送、删除、付款等副作用时会暂停并请求确认。

# 第 6 阶段：RAG 与知识库

## 目标

让智能体能够基于自己的文档回答问题，并提供来源，减少胡编乱造。

## 第 14 步：理解 RAG 的完整流程

RAG，即检索增强生成，分为两个阶段。

建立知识库：

```text
读取文档
  -> 清洗文本
  -> 分块
  -> 生成向量
  -> 保存向量和元数据
```

回答问题：

```text
用户问题
  -> 生成问题向量
  -> 检索相似片段
  -> 可选重排序
  -> 将片段交给模型
  -> 生成带来源的回答
```

需要掌握的概念：

- 文档解析。
- 文本分块。
- Embedding。
- 向量索引。
- 相似度检索。
- 元数据过滤。
- 重排序。
- 来源引用。

## 第 15 步：先做最简单的本地文档检索

动手任务：

准备 5～10 篇 Markdown 或 TXT 文档，实现：

1. 读取所有文档。
2. 按段落或标题切分。
3. 为每个片段保存文件名和标题。
4. 根据用户问题检索相关片段。
5. 将检索结果显示出来。

先不要急着让模型回答，先确认检索结果是否真的相关。

## 第 16 步：完成知识库问答

为检索系统增加模型回答，要求：

- 只能根据检索片段回答。
- 回答后列出来源文件。
- 找不到足够依据时回答“资料中没有找到相关信息”。
- 不允许把来源不存在的内容说成事实。

测试集至少包含：

- 文档中有明确答案的问题。
- 需要综合多个文档片段的问题。
- 文档中完全没有答案的问题。
- 使用同义词提问的问题。
- 可能误召回的问题。

## 第 17 步：改进检索质量

依次尝试：

1. 调整分块大小。
2. 增加分块重叠。
3. 保存标题、作者、日期等元数据。
4. 加入关键词检索。
5. 调整检索数量。
6. 增加重排序。
7. 对问题进行改写。

不要同时修改所有参数。每次只改一个因素，并记录测试结果。

进入下一阶段的标准：

- 能解释一次回答使用了哪些文档片段。
- 能识别“检索错了”和“模型理解错了”的区别。
- 找不到资料时不会强行回答。

# 第 7 阶段：记忆与状态管理

## 目标

让应用能够处理连续任务，同时避免把所有内容无限塞进上下文。

## 第 18 步：区分三类记忆

### 当前上下文

当前请求和近期对话，用于完成眼前任务。

### 会话记忆

当前会话中已经确认的目标、约束和中间结果。

### 长期记忆

用户明确允许保存的偏好或长期信息，例如喜欢的输出格式。

不要默认保存敏感信息，也不要把所有聊天内容都当作长期记忆。

## 第 19 步：实现会话状态

动手任务：

为知识库助手增加：

- 会话 ID。
- 当前用户问题。
- 最近若干轮对话。
- 最近一次检索结果。
- 当前任务状态。
- 清空会话功能。

当历史过长时：

- 删除不重要的旧消息，或
- 先总结旧消息，再把总结放入上下文。

进入下一阶段的标准：

- 多轮提问能够正确理解“它”“上面提到的内容”等指代。
- 会话过长时不会无限增加请求成本。
- 用户可以清除会话状态。

# 第 8 阶段：评估、日志与安全

## 目标

让智能体从 Demo 变成可以被检查、调试和改进的应用。

## 第 20 步：建立测试集

至少准备以下测试类型：

- 正常问题。
- 边界问题。
- 缺少信息的问题。
- 文档外问题。
- 恶意或越权问题。
- 需要工具调用的问题。
- 工具失败的问题。
- 超长输入。

每条测试记录：

```text
输入
期望行为
实际输出
是否通过
失败原因
修复方式
```

## 第 21 步：定义评估指标

根据项目选择指标：

- 任务成功率。
- 分类准确率。
- 字段提取准确率。
- RAG 检索命中率。
- 来源引用正确率。
- 工具调用正确率。
- 拒答准确率。
- 平均响应时间。
- 单次请求成本。

不要只评估“回答听起来是否自然”。

## 第 22 步：增加日志与可观测性

至少记录：

- 请求 ID。
- 时间。
- 用户请求长度。
- 使用的模型。
- 模型耗时。
- 工具名称和参数摘要。
- 检索到的文档 ID。
- 错误类型。
- 估算成本。

注意：日志中不要保存不必要的密码、API Key、身份证号和完整敏感内容。

## 第 23 步：学习基本安全控制

必须理解并处理：

- 提示词注入。
- 恶意文档内容。
- 越权访问。
- 敏感信息泄露。
- 不安全的代码执行。
- 工具参数篡改。
- 无限循环和高额费用。
- 外部 API 的超时与限流。

安全原则：

1. 外部网页和文档内容都视为不可信输入。
2. 模型不能直接决定权限。
3. 具有副作用的操作必须经过代码校验。
4. 高风险操作需要人工确认。
5. 工具使用最小权限。
6. 所有外部调用设置超时、重试上限和费用上限。

进入下一阶段的标准：

- 你有一套可重复运行的测试集。
- 你能定位一次失败发生在哪个步骤。
- 你能说明应用有哪些安全限制。

# 第 9 阶段：Web 服务与部署

## 目标

把命令行程序变成别人可以使用的应用。

## 第 24 步：封装成 API

学习内容：

- HTTP 方法。
- JSON 请求与响应。
- API 路由。
- 请求参数校验。
- 错误码。
- 跨域和认证的基本概念。

建议使用 FastAPI，制作以下接口：

```text
POST /chat
POST /documents
GET  /documents
GET  /health
DELETE /sessions/{session_id}
```

## 第 25 步：制作简单页面

页面至少包含：

- 对话输入框。
- 回答区域。
- 来源展示区域。
- 工具调用状态。
- 错误提示。
- 清空会话按钮。

先保证功能和错误状态完整，再考虑视觉设计。

## 第 26 步：学习部署基础

需要理解：

- 生产环境变量。
- 密钥管理。
- 日志查看。
- 数据持久化。
- Docker 基础。
- HTTPS。
- 访问权限。
- 资源和费用限制。

部署前检查：

- API Key 没有写进前端。
- 生产环境不会暴露调试信息。
- 文件上传有大小和类型限制。
- 接口有超时和限流。
- 用户数据有清理策略。

进入下一阶段的标准：

- 能在本地以外的环境运行应用。
- 能查看错误日志并定位问题。
- 能说明应用的限制和费用风险。

# 四、推荐学习顺序与技术选择

## 先学什么

1. Python 基础。
2. HTTP、JSON 和 API。
3. 模型调用。
4. 提示词和结构化输出。
5. 工具调用。
6. 工作流和状态。
7. RAG。
8. 评估与安全。
9. Web 服务和部署。

## 暂时不要先学什么

- 多智能体协作。
- 复杂自主规划。
- 大规模模型训练。
- 从零实现 Transformer。
- 同时学习多个智能体框架。
- 没有测试就追求“全自动执行”。

## 推荐起步技术栈

- 语言：Python。
- 模型调用：所选模型厂商的官方 SDK。
- 数据校验：Pydantic 或 JSON Schema。
- Web API：FastAPI。
- 文本处理：Python 标准库加成熟解析库。
- 向量检索：先使用简单本地索引，再根据需求选择向量数据库。
- 编排：先使用普通 Python 函数和状态对象，复杂后再引入框架。
- 版本管理：Git。

框架和模型 SDK 会不断变化。长期更重要的是理解任务拆解、工具边界、检索原理、测试方法和安全控制。

# 五、每天的学习方式

每次学习建议分成四部分：

1. **理解概念，约 20% 时间**：阅读官方文档或教程。
2. **编写最小代码，约 40% 时间**：只实现当前概念。
3. **测试失败案例，约 30% 时间**：主动构造异常输入。
4. **整理笔记，约 10% 时间**：记录输入、输出、错误和改进方式。

每周至少保留一个可以运行的版本。不要只收藏教程，也不要只复制示例代码。

# 七、最简执行版

如果时间有限，只完成下面 8 步：

1. 学会 Python、JSON 和环境变量。
2. 调用一次模型 API。
3. 让模型输出可校验的 JSON。
4. 封装一个计算器或文件搜索工具。
5. 实现一个三步工作流。
6. 给 5 篇文档做 RAG 问答。
7. 为 20 个问题建立测试集。
8. 用 FastAPI 或简单页面部署出来。

这 8 步完成后，你已经具备了继续学习复杂智能体框架的基础。

## 一句话总结

先学会稳定调用模型，再学会让模型调用工具；然后让它基于可靠资料工作，最后补上状态管理、评估、安全和部署。每学一个主题，都用一个可以运行的小项目验证。
